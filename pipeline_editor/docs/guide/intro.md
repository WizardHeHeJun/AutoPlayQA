# 是什么

先弄清 PipelineEditor 编辑的到底是什么，以及界面上各个区域分别负责什么。

为 AutoPlayQA（识别门控任务引擎）构建的 Web 可视化编辑器：
画布拖拽编排任务状态机、属性面板编辑识别/动作、真值校验 + lint、
截图取 ROI/模板、真机运行实时高亮、套件编排与报告查看。
编辑器随框架仓库分发在 `pipeline_editor/`。

面向第一次打开这个编辑器的 QA / 开发。编辑对象就是 AutoPlayQA 的任务文件
`task/task_definitions/<任务名>.json`（套件在其下的 `suites/`），
编辑器不另存一份副本——画布上的每一次改动最终都写回这个 JSON。
浏览器打开 <http://127.0.0.1:5173>。

## 界面总览

顶栏四页：**任务**（`/`，任务列表）、**套件**（`/suites`）、**报告**（`/reports`）、
**工具**（`/tools`）。从任务列表点进某个任务即进入编辑器页 `/tasks/<name>`，它分四个区：

| 区域 | 位置 | 内容 |
| --- | --- | --- |
| 工具条 | 顶部一行 | 返回列表、任务名、未保存/运行中标记、保存、撤销/重做、新建节点、自动布局、重排步号、跳转层与详情两个开关、校验错误红条 |
| 节点大纲 | 左侧 220px | 全部节点按**步号**排序，分支按层级缩进；点一行 = 选中该节点 |
| 画布 | 中间 | React Flow：节点卡片 + 三类边，右下角有缩放控件与小地图 |
| 属性面板 | 右侧 360px | 四个 Tab：**节点** / **任务设置** / **问题**（带问题数徽标） / **运行** |

四个区在一屏内对齐：顶部工具条横贯整宽，左侧是按步号排序的节点大纲，
中间是画布，右侧「节点」Tab 正在编辑当前选中的节点。
