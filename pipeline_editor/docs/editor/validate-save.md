# 校验、lint 与保存

改完图之后，编辑器怎么判断这份任务是对的，以及按下 `Ctrl+S` 之后到底发生了什么。

## 校验、lint 与问题面板

- **真值校验**：停止编辑 0.8 秒后自动把当前 doc 发给后端干跑
  `task_loader.resolve_task`（编辑器不复刻任何校验规则）。通过则回填步号（大纲和卡片上的
  编号随之更新）；不通过则工具条弹红条、出错节点红描边，问题面板里以「校验」标签列出。
- **lint**：后端 `lint_task` 的规则性提示（标签是规则 ID），在**保存**时随响应返回；
  有提示时保存后会自动切到「问题」Tab。
- **本地提示**（标签「本地」）：前端即时算的三类——悬空引用
  （`next`/`on_timeout`/`entry`/`on_finding`/`skip_to` 指向不存在的节点）、
  `and`/`or` 里 ≥2 个 `ui_text`、组合嵌套超过 2 层。
  **画布上"少了一条线"通常就是悬空引用**：目标节点不存在时不画边，只报错。
- 问题面板把三类合并展示、error 排前，点任意一条即定位到对应节点（并给它红描边）。
  Tab 上的徽标数 = 校验错误 + 后端 lint 条数。

![问题面板](/screenshots/problems-panel.png)

*「问题」Tab：每条前面是来源标签（「校验」/ 规则 ID / 「本地」）+ 节点名，点一条即定位到该节点。*

> [!NOTE]
> 后端没起时真值校验这一步静默跳过，不打扰编辑。

## 保存

`Ctrl+S` 或工具条「保存」。有未保存修改时任务名旁会挂橙色「未保存」标签，
带着未保存修改关标签页会被浏览器拦一下。保存做了这些事：

1. **序列化**：剔掉派生字段 `_merge` / `_steps` / `_step_outline`，剔掉所有 include
   来源的节点；其余顶层键**原样保留**——包括你写的 `_comment`、`includes`、
   `on_conflict`、`defaults`、`popups`、`watchdogs`，且不打乱键顺序。
2. **后端校验 + lint**：再跑一次 `resolve_task`，失败就不写盘，直接把错误定位到节点
   并切到「问题」Tab。若 AutoPlayQA 的 config 打开了 `lint.strict`，有任何 lint 警告
   也会拒绝保存。
3. **写盘**：以 `indent=2` 重写任务文件，提示「已保存（N 节点，M 条 lint 提示）」。
   round-trip 是**语义无损**的：不做修改的「打开→保存」JSON 深度相等（有回归测试守着），
   但格式统一成 `indent=2`，可能与手写原文的排版不同。
4. **乐观锁**：请求带上载入/上次保存时看到的文件版本。若磁盘上已有更新的修改
   （AI/MCP 或手改），后端拒绝写入，前端提示「保存已被拒绝」并弹出冲突横幅
   （见 [AI / MCP 协同编辑](/editor/ai-mcp)）。

> [!TIP]
> 「未保存」只看**将写盘的那部分**：拖动节点改坐标、切换详情/跳转层开关都不会让任务变脏
> （坐标有自己的 sidecar 自动保存）。
